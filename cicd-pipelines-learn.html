What is CI/CD?

Continuous Integration, Delivery & Deployment

CI/CD automates software building, testing, and deployment to deliver code changes faster, safer, and with zero manual overhead.

🔄

Continuous Integration (CI)

Developers merge code changes into Git frequently. Automated pipelines trigger immediately to compile code and run unit tests.

📦

Continuous Delivery (CD)

Automates building release artifacts (Docker images, `.jar` files) and deploying to staging environments ready for one-click manual production approval.

⚡

Continuous Deployment

Extends Continuous Delivery by automatically releasing every passing code commit directly to end-user production with zero human intervention.

Artifact Management (Nexus & Artifactory)

Centralized Storage for Build Outputs

Artifact repositories store versioned binaries (.jar files, npm packages, Docker images) produced by build jobs for reliable deployment.

🏛️

Nexus Repository Manager

Popular open-source artifact repository. Supports Hosted (internal builds), Proxy (external dependency caching), and Group repositories.

🐸

JFrog Artifactory

Enterprise universal repository manager. High availability, vulnerability scanning (Xray), and native integration with all major CI/CD engines.

Container & Automated Testing Integration

Testing & Container Deployment Automation

Automated test suites (Unit, Integration, UI) execute in pipeline stages before container image building and Kubernetes cluster deployment.

# Standard Pipeline Container Build & K8s Deploy Stage
$ npm test   # 1. Execute Unit & Integration Tests
$ docker build -t registry.company.com/myapp:${BUILD_NUMBER} .   # 2. Build Image
$ docker push registry.company.com/myapp:${BUILD_NUMBER}   # 3. Push Artifact
$ kubectl apply -f k8s/deployment.yaml   # 4. Trigger K8s Rolling Update

Scripted vs. Declarative Jenkinsfiles

// 1. Scripted Pipeline (Groovy Code)
node {
  stage('Build') {
    sh 'mvn clean install'
  }
  stage('Test') {
    sh 'mvn test'
  }
  stage('Deploy') {
    sh './deploy.sh'
  }
}
// 2. Declarative Pipeline (Recommended)
pipeline {
  agent any
  stages {
    stage('Build') {
      steps { sh 'mvn clean install' }
    }
    stage('Test') {
      steps { sh 'mvn test' }
    }
  }
}

GitHub Actions Workflows

Native CI/CD Inside GitHub Repositories

Workflows are declared as YAML manifests stored inside your repository at .github/workflows/*.yml.

# .github/workflows/ci.yml
name: CI Pipeline
on: [push]

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
    - name: Checkout code
      uses: actions/checkout@v3
    - name: Run Build & Test
      run: |
        npm install
        npm test

Matrix Builds & Event Triggers

Multi-Job Parallel Execution & Event Triggers

Test across multiple operating systems or runtime versions in parallel using Matrix strategies.

# GitHub Actions Matrix Strategy & Event Triggers
on:
  push:
    branches: [main]
  pull_request:
  workflow_dispatch:   # Manual trigger button

jobs:
  test:
    runs-on: ubuntu-latest
    strategy:
      matrix:
        node-version: [14, 16, 18]
    steps:
    - run: echo "Testing on Node ${{ matrix.node-version }}"

Pipeline Security & Secrets Management

Secrets Management
