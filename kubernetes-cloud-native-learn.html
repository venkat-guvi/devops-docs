Introduction to Kubernetes & Architecture

What is Kubernetes (K8s)?

Kubernetes is an open-source container orchestration system for automating application deployment, scaling, and management across cluster nodes.

🏛️

Monolithic Architecture

Entire application built as a single, tightly coupled unit. Difficult to scale independently and hard to update.

🧩

Microservices Architecture

Application broken into small, independent services communicating via APIs. Highly scalable and container-friendly.

Control Plane vs. Worker Node Components

🎮 Control Plane (Master Node)

  • API Server: Central management REST endpoint for all cluster operations.
  • etcd: Distributed, consistent key-value store for cluster state.
  • Scheduler: Binds unscheduled Pods to suitable Nodes based on resources.
  • Controller Manager: Runs control loops (node, replica, endpoint controllers).

👷 Worker Node Components

  • Kubelet: Node agent watching PodSpecs and reporting node status back to API server.
  • Kube-Proxy: Maintains network routing rules for Service endpoints.
  • Container Runtime: Engine running container pods (containerd, CRI-O).

Kubernetes Core Objects

Cluster Building Blocks & Blueprints

Kubernetes objects represent persistent state entities in your cluster. You define them declaratively using YAML manifests.

ObjectPurpose & Behavior
NamespaceVirtual cluster inside a cluster. Isolates environments (e.g. dev, prod).
PodSmallest deployable unit in K8s. Encapsulates one or more co-located containers. Ephemeral in nature.
DeploymentDeclarative manager for stateless application Pods. Controls replica counts, rolling updates, and rollbacks.
ReplicaSetEnsures specified number of identical Pod replicas are running at all times. Managed automatically by Deployments.
StatefulSetManages stateful apps (databases). Provides stable, unique network identifiers (e.g. pod-0) and persistent storage.
DaemonSetEnsures a copy of a Pod runs on all (or selected) worker nodes (e.g. Fluentd logging, Prometheus node-exporter).
JobExecutes short-lived batch tasks to completion and terminates automatically.

Kubernetes Services & Networking

Networking Abstraction & Traffic Routing

Every Pod gets its own IP address. A Service provides a stable IP address and DNS name to access a set of dynamic Pods.

Service TypeAccessibilityUse Case
ClusterIP (Default)Internal to cluster onlyMicroservice-to-microservice communication
NodePortExternal on node port (30000-32767)Development testing or external access without cloud LB
LoadBalancerExternal via Cloud Provider LBProduction web applications hosted on AWS/GCP/Azure
# Ingress Controller Example (Smart Web Router)
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: app-ingress
spec:
  rules:
  - host: myapp.com
    http:
      paths:
      - path: /
        pathType: Prefix
        backend:
          service:
            name: my-service
            port:
              number: 80
📌 K8s DNS Format: Every service gets an automatic internal domain: service-name.namespace.svc.cluster.local (e.g. backend.default.svc.cluster.local).

ConfigMaps & Secrets

Decoupling Configuration from Container Code

Store application configuration parameters separately from application image builds.

📄

ConfigMap

Stores non-sensitive key-value configuration data (e.g. database hostnames, feature flags, log levels).

🔒

Secret

Stores sensitive data (passwords, API keys, TLS certificates) stored as Base64-encoded strings with encryption option.

# Injecting ConfigMap as Environment Variable in Pod
env:
  - name: DATABASE_HOST
    valueFrom:
      configMapKeyRef:
        name: app-config
        key: db_host

Kubernetes Scaling & HPA

✋

Manual Scaling

Manually adjust replica counts using kubectl scale command.

$ kubectl scale deploy myapp --replicas=5
🤖

Horizontal Pod Autoscaler (HPA)

Automatically adjusts replica count based on CPU/RAM usage metrics.

$ kubectl autoscale deploy myapp --cpu-percent=50 --min=1 --max=10
🚀
08 / 10

Deployment Strategies

🔄

RollingUpdate (Default)

Updates Pods one-by-one with zero cluster downtime (maxSurge / maxUnavailable).

⏹️

Recreate

Terminates all existing Pods simultaneously before launching the new version. Brief downtime.

🟦🟩

Blue / Green

Runs old (Blue) and new (Green) versions in parallel; switches router/service traffic instantaneously.

🐤

Canary

Deploys new version to a small percentage of live users before full rollout.

⚓

Helm Package Manager & Managed K8s

Helm: The Package Manager for Kubernetes

Helm packages pre-configured Kubernetes resources into reusable Helm Charts with versioning and rollback capabilities.

$ helm repo add bitnami https://charts.bitnami.com/bitnami
$ helm install my-db bitnami/postgresql   # Deploy app stack in seconds
$ helm list   # List installed releases
