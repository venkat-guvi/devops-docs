Version Control System

A Version Control System (VCS) is a tool that helps track changes in files over time. It allows multiple users to work on the same project without overwriting each other’s work.

It stores every version of the file, so you can go back to previous versions whenever needed.

Simple idea: It is like a history + backup system for your code.

Why use Version Control?

Tracks all changes made in files

Helps multiple developers work together

Allows rollback to previous versions

Prevents accidental data loss

Types of VCS

Centralized VCS

These systems have a single server that contains the versioned files, and some clients to check out files from a central place.

Distributed VCS

In a Distributed Version Control System (such as Git, Mercurial, Bazaar or Darcs), the user has a local copy of a repository.

So, the clients don't just check out the latest snapshot of the files even if they can fully mirror the repository.

The local repository contains all the files and metadata present in the main repository.

Git Fundamentals

Git is a distributed version control system used to manage and track changes in source code during development.

It was created to make collaboration easier and faster.

Git stores:

File changes

History of changes

Author of changes

Basic Git Workflow

Working Directory → Where files are created/edited

Staging Area → Files ready to be committed

Repository → Permanent storage of changes

Flow: Edit → Add → Commit

Git Repository Management

A repository (repo) is a storage location where your project files and their history are stored.

Types of Repository

Local Repository → Stored on your computer

Remote Repository → Stored on servers (like GitHub)

Commands

$ git init command

Creates a new Git repository.

Example:

$ git init
$ git clone command

Copies an existing repository from a remote server.

Example:

$ git clone https://github.com/user/repo.git
$ git status command

Shows the current status of files (modified, staged, untracked).

Example:

$ git status
$ git add command

Adds files to the staging area.

Example:

$ git add file.txt

Add all files:

$ git add .
$ git commit command

Saves changes to the repository.

Example:

$ git commit -m "Added new file"

Git Branching Strategies

Branching allows developers to work on different features without affecting the main code.

Simple idea: Branches are like separate versions of your project.

Commands

$ git branch command

Lists all branches.

Example:

$ git branch

Create branch

$ git branch feature1
$ git checkout command

Switches to another branch.

Example:

$ git checkout feature1

Create and switch:

$ git checkout -b feature1
$ git merge command

Combines one branch into another.

Example:

$ git merge feature1

Git Collaboration Workflows

Git allows multiple developers to collaborate on the same project.

Common Workflow

Clone repository

Create a branch

Make changes

Add & commit changes

Push to remote

Commands

$ git pull command

Fetches latest changes from remote repository.

Example:

$ git pull origin main
$ git push command

Uploads local changes to remote repository.

Example:

$ git push origin main

Pull Requests & Code Reviews

A Pull Request (PR) is used to request merging your changes into the main branch.

Steps:

Push your branch

Create Pull Request

Team reviews code

Merge after approval

Benefits:

Improves code quality

Detects bugs early

Encourages collaboration
