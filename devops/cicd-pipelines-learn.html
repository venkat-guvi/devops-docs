What is CI/CD?

CI/CD (Continuous Integration and Continuous Delivery) is a method used in DevOps to automate the process of building, testing, and deploying applications.

Simple idea: Automatically build → test → deploy your code

📌
03 / 22

What is Continuous Integration (CI)?

Continuous Integration is the process of automatically integrating code changes into a shared repository.

Developers push code frequently

Code is automatically built and tested

Errors are detected early

📌
04 / 22

What is Continuous Delivery (CD)?

Continuous delivery is a software development practice that uses automation to speed the release of new code.

It establishes a process through which a developer’s changes to an application can be pushed to a code repository or container registry through automation.

📌
05 / 22

What is Continuous Deployment?

Continuous deployment is an extension of continuous delivery, and can refer to automating the release of a developer’s changes from the repository to production, where it is usable by customers.

Build Automation

Build automation means automatically compiling and packaging code.

Tools used:

Maven (Java)

npm (Node.js)
pip (Python)

Why Build Automation?

Saves time

Reduces human errors

Ensures consistent builds

Speeds up development

Example: Instead of running multiple commands manually, one command builds the entire project.

Dependencies are installed

Tests may run

.zip file

Types of Pipelines

There are two types of pipelines in Jenkins:

Scripted Pipeline

Declarative Pipeline

Scripted Pipeline

Scripted Pipeline is the older and more flexible way of writing pipelines.

Based on Groovy scripting language

Full control over logic

More complex and verbose

📌
10 / 22

Features

Highly customizable

Supports complex logic

Requires programming knowledge

Example

node {

stage('Build') {

// Build the application

sh 'mvn clean install'

}

stage('Test') {

// Run tests

sh 'mvn test'

}

stage('Deploy') {

// Deploy application

sh 'deploy.sh'

}

}



Explanation

node → Defines execution environment

stage → Represents steps (Build, Test, Deploy)

sh → Runs shell commands

Flow: Build → Test → Deploy

Declarative Pipeline

Declarative Pipeline is a newer and simpler way to write pipelines.

Uses structured syntax

Easier to read

Less error-prone

📌
11 / 22

Features

Simple and readable

Recommended for beginners

Uses predefined structure

Example

pipeline {

agent any

stages {

stage('Build') {

steps {

sh 'mvn clean install'

}

}

stage('Test') {

steps {

sh 'mvn test'

}

}

stage('Deploy') {

steps {

sh 'deploy.sh'

}

}

}

}



Explanation

pipeline → Main block

agent any → Runs on any available node

stages → Groups all stages

steps → Commands inside each stage

Flow remains same: Build → Test → Deploy

What is a Workflow?

A workflow is a defined automation process in GitHub Actions.

Stored as a .yml file

Located in .github/workflows/

Runs on specific events

Example Workflow File

name: CI Pipeline

on: push

jobs:

build:

runs-on: ubuntu-latest

steps:

- name: Checkout code

uses: actions/checkout@v3

- name: Run build

run: echo "Building project"



Key Components

ComponentDescription
WorkflowAutomation process
JobGroup of steps
StepIndividual task
ActionPre-built reusable code
RunnerMachine that runs jobs
