What is Configuration Management?

Configuration Management is the process of automating system setup, software installation, and maintaining consistent environments.

Simple idea: Instead of manually configuring servers → use automation tools

Why is it Important?

Ensures consistency across servers

Saves time

Reduces human errors

Makes scaling easier

Real Example

Without automation:

Install software manually on each server

With configuration management:

Run one command → All servers configured automatically



Ansible

Ansible is a software tool that enables cross-platform automation and orchestration at scale and has become over the years the standard choice among enterprise automation solutions.

It’s mostly addressed to IT operators, administrators, and decision-makers, helping them achieve operational excellence across their entire infrastructure ecosystem.

Backed by RedHat and a loyal open source community, it is considered an excellent option for configuration management, infrastructure provisioning, and application deployment use cases.

Configuration Management Concepts

Key Concepts

Idempotency → Running the same script multiple times gives same result

Automation → No manual work

Consistency → Same setup everywhere

Scalability → Manage many servers easily

Inventory Management

Ansible inventory is a crucial component in Ansible, helping you manage the hosts you want to automate tasks on. It defines a collection of hosts, which can be grouped, organized, and assigned variables. There are two main types of Ansible inventory:

Static Host Inventory: Manually created text files with a list of hosts, groups, and variables. Suitable for a set of servers that don’t change frequently.

Dynamic Host Inventory: Generated dynamically using Ansible plugins based on external information sources. Ideal for large, dynamic environments with frequently changing hosts.

Playbook

Playbooks are the files where Ansible code is written. Playbooks are written in YAML format. YAML stands for Yet Another Markup Language.

Playbooks are one of the core features of Ansible and tell Ansible what to execute. They are like a to-do list for Ansible that contains a list of tasks.

Playbooks contain the steps which the user wants to execute on a particular machine. Playbooks are run sequentially.

Playbooks are the building blocks for all the use cases of Ansible.

Example

- hosts: web

become: yes

tasks:

- name: Install nginx

apt:

name: nginx

state: present

Ansible Roles

Roles provide a framework for fully independent, or interdependent collections of variables, tasks, files, templates, and modules.

In Ansible, the role is the primary mechanism for breaking a playbook into multiple files.

This simplifies writing complex playbooks, and it makes them easier to reuse. The breaking of the playbook allows you to logically break the playbook into reusable components.

Each role is basically limited to a particular functionality or desired output, with all the necessary steps to provide that result either within that role itself or in other roles listed as dependencies.
