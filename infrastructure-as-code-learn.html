What is Infrastructure as Code (IaC)?

Code-Driven Infrastructure Management

Infrastructure as Code (IaC) is the DevOps practice of managing and provisioning servers, networks, databases, and storage through version-controlled definition files rather than manual UI clicks.

📜 Imperative Approach

Defines step-by-step procedural instructions on HOW to achieve a setup (e.g. Shell scripts, AWS CLI commands).

🎯 Declarative Approach (Terraform)

Defines WHAT the desired final state should look like. The underlying engine calculates the diff and reaches the target state automatically.

Terraform Architecture & Providers

How Terraform Interacts with Cloud APIs

Terraform uses Providers as logical API plugins to interact with over 130+ cloud platforms (AWS, Azure, GCP, Kubernetes, GitHub).

# Provider Block Example (main.tf)
provider "aws" {
  region = "us-east-1"
  profile = "production"
}

HCL Syntax & Core Blocks

HashiCorp Configuration Language (HCL)

HCL files (.tf extension) use structured blocks to declare infrastructure objects.

# 1. Terraform Version & Provider Block
terraform {
  required_providers {
    aws = { source = "hashicorp/aws", version = "~> 4.0" }
  }
}

# 2. Resource Block (Creates EC2 Virtual Server)
resource "aws_instance" "web_server" {
  ami = "ami-005e54dee72cc1d00"
  instance_type = "t2.micro"
}

Provisioners (`local-exec` & `remote-exec`)

Post-Creation Script Execution

Provisioners execute setup scripts on your local machine or inside the newly created remote EC2 instance.

resource "aws_instance" "web" {
  ami = "ami-12345"

  # Runs on local machine executing Terraform
  provisioner "local-exec" {
    command = "echo ${self.public_ip} >> ips.txt"
  }

  # Runs over SSH on the newly created instance
  provisioner "remote-exec" {
    inline = ["sudo apt update", "sudo apt install -y nginx"]
  }
}

Terraform State Management (`terraform.tfstate`)

Mapping Code to Real-World Infrastructure

Terraform records metadata about created cloud resources in a JSON state file (terraform.tfstate). State allows Terraform to detect drift and update only changed infrastructure.

⚠️ Important: The state file contains sensitive raw attributes (passwords, private IPs). Never commit terraform.tfstate directly to Git repositories!

Terraform Backends (Local vs. Remote S3)

💻

Local Backend (Default)

Stores state file on local developer disk. Unsuitable for team collaboration due to missing state locking and conflict risks.

☁️

Remote S3 + DynamoDB Backend

Stores state in Amazon S3 bucket with DynamoDB table state locking to prevent concurrent apply race conditions.

# Remote S3 Backend Configuration
terraform {
  backend "s3" {
    bucket = "my-company-tf-state"
    key = "prod/terraform.tfstate"
    region = "us-east-1"
    dynamodb_table = "terraform-locks"
  }
}

Terraform CLI Commands Cheat Sheet

CommandPurpose & Action
