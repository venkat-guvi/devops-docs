Configuration Management & Idempotency

Automated System Setup & Consistency

Configuration Management automates server setup, software installation, and system state enforcement to maintain consistent environments across hundreds of machines.

⚡

Idempotency

Running the same Ansible automation script multiple times yields the exact same desired state without unintended side effects.

🎯

Consistency

Eliminates human manual setup errors. Guarantees dev, staging, and production servers have identical configurations.

📈

Scalability

Execute one command to configure 1 or 1,000 servers simultaneously over SSH in minutes.

Task Automation & Configuration Enforcement

State Enforcement & Drift Remediation

Tasks declare desired system state. If a package is uninstalled or a service crashes, Ansible automatically restores it to present or started.

# Task Example: Install and ensure Nginx is running
- name: Install Nginx web server package
  apt:
    name: nginx
    state: present

- name: Ensure Nginx service is running and enabled on boot
  service:
    name: nginx
    state: started
    enabled: yes

Ansible YAML Playbooks

Playbook Syntax & Structure

Playbooks are declarative YAML files containing sequential lists of tasks executed on designated host groups.

--- # Standard Playbook (deploy_web.yml)
- hosts: web
  become: yes   # Privilege escalation (sudo)
  tasks:
    - name: Install Nginx
      apt:
        name: nginx
        state: present
    - name: Copy custom index page
      copy:
        src: files/index.html
        dest: /var/www/html/index.html

Ansible Roles & Directory Structure

Modular Playbook Architecture

Roles break complex playbooks into modular, reusable directory components (tasks, handlers, templates, variables).

# Standard Project Directory
ansible.cfg
hosts   # Inventory file
Guvi.yml   # Main playbook
roles/
  install-tomcat/
    tasks/main.yml
    handlers/main.yml
  start-tomcat/
    tasks/main.yml
# Main Playbook (Guvi.yml)
---
- hosts: tomcat-node
  become: yes
  roles:
    - install-tomcat
    - start-tomcat

# Execution Command
$ ansible-playbook -i hosts Guvi.yml

Ansible Ad-Hoc Commands

Quick One-Off Remote Commands

Ad-hoc commands execute single tasks across target hosts without writing a full playbook.

ModuleAd-Hoc Command ExampleAction
pingansible all -m pingTests SSH connectivity to all inventory servers
shellansible all -m shell -a "uptime"Runs shell command and prints remote host uptime
copyansible web -m copy -a "src=app.tar dest=/tmp/"Copies local file to all web servers
aptansible web -m apt -a "name=curl state=present" --becomeInstalls curl package using sudo root privileges
serviceansible web -m service -a "name=nginx state=restarted" --becomeRestarts Nginx service on target servers

Privilege Escalation & Sudo Options

Running Tasks with Root Privileges

Use --become (or become: yes in playbooks) to execute tasks with elevated sudo permissions on remote systems.

$ ansible all -u ubuntu -m apt -a "name=htop state=present" --become

Ansible Vault & Ansible Galaxy

🔒

Ansible Vault (Secrets)

Encrypts sensitive variables and playbook files (passwords, SSL keys) with AES-256 encryption.

$ ansible-vault encrypt secrets.yml
$ ansible-vault view secrets.yml
🌐

Ansible Galaxy (Community Roles)

Public repository for sharing pre-built community Ansible roles.

$ ansible-galaxy install geerlingguy.nginx
$ ansible-galaxy init my_new_role
