Part 1: Introduction to Typography System

What is a Typography System?

A typography system is a deliberate, documented set of rules that governs how type is used across a product. It is not just choosing a font - it is defining every dimension of how text behaves: size, weight, spacing, family, and hierarchy.

The keyword is system. Individual type choices are design decisions. A typography system is a design infrastructure that makes consistent, scalable, and accessible type decisions possible across an entire product and team.

Why Systems Over Individual Decisions?

Without a Typography System

With a Typography System

Headings vary by 2-4px across screens

All headings use the same token: --font-size-4xl

Line height is set differently by each designer

Line height is a defined token applied globally

New screens require new type decisions

New screens inherit the system automatically

Accessibility is checked after the fact

Accessibility is baked into the token values

Engineers interpret type specs inconsistently

Engineers implement tokens exactly as defined

Design looks polished in isolation, broken in context

Design is consistent at scale and across devices

Part 2: Why Typography is the Backbone of UI

The Dominant Element in Any Interface

The Four Functions of Typography in UI

Function

What It Does

UI Example

Hierarchy

Tells users what to look at first, second, and third. Creates a reading path.

A page with a 48px headline, 18px subheading, and 15px body creates an unambiguous visual sequence

Readability

Makes text physically easy to read through size, spacing, and contrast.

Body text at 16px, line-height 1.6, on a white background with dark text - effortless to read

Brand Expression

Communicates personality, tone, and values through font choice and style.

A luxury brand uses a high-contrast serif. A tech startup uses a geometric sans-serif.

Information Architecture

Groups, separates, and structures content through typographic differentiation.

A bold label above a light input field communicates: this is the category, that is the data

How Typography Signals Trust

Consistent type hierarchy signals that the product was built with care and intention

Readable body text signals that the product respects the user's time and effort

Appropriate font choice for the domain signals domain competence: a medical app using a clean, readable sans-serif signals professionalism

Poor typography signals neglect: if the text is inconsistent, users assume other aspects of the product are too

Research finding: Stanford Web Credibility Research found that typography and visual design are among the top factors users cite when evaluating website credibility

Part 3: Understanding Type Anatomy

The Baseline System

Type Anatomy Reference

Anatomical Part

Definition

Why It Matters in UI Design

Baseline

The invisible line on which most letters sit. The foundation of vertical alignment in type.

Affects text alignment and optical weight distribution in UI

Cap Height

The height of uppercase letters measured from baseline to top of a capital letter.

Determines the visual size and weight of headings in UI

X-Height

The height of lowercase letters (specifically the letter x). Critical for readability.

High x-height = more readable at small sizes. Major factor in choosing body fonts.

Ascender

The part of a lowercase letter that rises above the x-height (b, d, f, h, k, l, t).

Ascenders add verticality and elegance. Affects minimum line-height requirements.

Descender

The part of a lowercase letter that drops below the baseline (g, j, p, q, y).

Descenders need space - affects line-height setting and vertical rhythm in layouts.

Counter

The enclosed or partially enclosed space within a letter (o, e, a, p, d).

Large counters improve readability at small sizes and on low-resolution screens.

Stem

The main vertical or diagonal stroke of a letter - the primary structural element.

Stem weight determines font weight. Thin stems = light, thick stems = bold.

Serif

Small decorative strokes at the ends of letter strokes (present only in serif typefaces).

Serifs aid reading at large sizes in print. Sans-serif outperforms at small screen sizes.

Part 5: Type Scale Deep Dive

What is a Type Scale?

A type scale is a structured set of font sizes that increase at a consistent ratio. Rather than choosing sizes arbitrarily, a type scale creates a mathematical relationship between every size level - producing visual harmony across all text elements.

When you look at a well-designed product and every heading and body text feels like it belongs together, that is a type scale working correctly. When sizes feel random and disconnected, there is no scale.

The Modular Scale

The modular scale uses a single base size and a ratio to generate all other sizes. The most common ratios produce harmonious progressions because they are based on musical intervals and mathematical constants.

Part 7: Typography in Design Systems

A typography design system is the formalisation of all type decisions into a set of documented, reusable tokens. Tokens replace ad-hoc decisions with a shared language between designers and engineers.

What are Typography Tokens?

A design token is a named variable that stores a design decision. Instead of a designer specifying 16px bold in every text element, they specify the token --font-size-base and --font-weight-bold. The token can be updated in one place and propagated everywhere instantly.

Semantic vs Primitive Tokens

A mature token system has two layers: primitive tokens that define the raw values, and semantic tokens that define the purpose. Semantic tokens are what designers and engineers use in practice. Primitive tokens are what semantic tokens reference.

Primitive Tokens (Raw Values)

Semantic Tokens (Purposeful Names)

--font-size-16: 16px

--body-font-size: var(--font-size-16)

--font-size-24: 24px

--heading-3-size: var(--font-size-24)

--font-weight-700: 700

--heading-font-weight: var(--font-weight-700)

--line-height-160: 1.6

--body-line-height: var(--line-height-160)

These define what exists in the system

These define how values are used

Changed only when the base design language changes

Changed when purpose or context changes without changing the raw value

Consistency Checklist for Typography in Design Systems

Every text style in Figma corresponds to a named token in the code

No text element uses a local style (one-off size or weight not in the system)

Font weights are referenced by token, not by numeric value

Line-height and letter-spacing are defined in the text style, not applied as overrides

The design system documentation includes a usage guide: when to use each level, with examples

Design system changes go through a versioning process: no silent updates to token values

Part 8 : Font Pairing Principles

The Core Principles of Font Pairing

Principle 1 - Contrast, not conflict: Paired fonts must be different enough to serve distinct roles but similar enough to feel intentional. The goal is productive contrast, not visual fighting.

Principle 2 - Shared DNA: The best pairings share subtle similarities - similar x-height, similar proportions, or a shared historical period - that creates subconscious harmony despite surface differences.

Principle 3 - Maximum two families: Most UI products use one or two typeface families. Three is occasionally acceptable. Four or more is always wrong.

Principle 4 - Function defines pairing: Identify the role (heading vs body vs code vs accent) before choosing fonts. Pair for function, not preference.

Principle 5 - Test with real content: A pairing that looks good with placeholder text may fail with actual product copy. Always test with real headlines and real paragraphs at real sizes.

Proven Font Pairings for UI Design

Common Pairing Mistakes

Pairing Mistakes

Why They Fail

Two sans-serif fonts with similar proportions

No contrast = no hierarchy. The fonts blend together. Users cannot distinguish heading from body.

Two serif fonts of similar style

Same problem - too similar. Feels monotonous without variety. No clear role differentiation.

Decorative display font for both heading and body

Beautiful for one word. Unreadable at paragraph length. The heading font was never designed for body text.

Fonts from completely different historical eras without intentional reason

The visual tones clash. A 16th-century humanist serif paired with a 1990s techno display font reads as confusion, not sophistication.

Pairing fonts with very different x-heights at the same size

Text elements appear mismatched in size even when the font-size value is identical.

Using three or more typeface families in one product

Visual complexity overwhelms the content. Users unconsciously perceive inconsistency and brand incoherence.

Part 9 : Responsive Typography

How Typography Behaves Across Devices

Device Context

Typical Viewport

Typography Adjustments Needed

Large Desktop (1440px+)

Wide, high-resolution

Display text can be 64-96px. Body text at 16-18px. Maximum line length rules become critical.

Standard Desktop (1280px)

Standard work context

H1 at 48-56px. Body at 16px. Type scale performs as designed.

Small Laptop (1024px)

Often used at angle/distance

H1 scales down to 40-48px. Body stays at 16px. Container widths reduce, so line length self-manages.

Tablet (768px)

Touch interaction primary

H1 at 36-40px. Body at 15-16px. Touch targets (buttons, links) need larger minimum sizes - 44px minimum.

Mobile (375-430px)

One-thumb use, small screen

H1 at 28-36px. Body at 14-16px. Tight vertical space means spacing must compress proportionally.

Small Mobile (320px)

Edge case but must work

H1 at 24-28px. Body at 14px minimum. Every pixel counts. Never drop below 14px body text.

Part 10 : Common Typography Mistakes in UI

These are the most damaging and most frequent typography errors found in real UI products. Understanding them is the fastest way to elevate your type decisions immediately.

Mistake

Pattern

Impact

Fix

Too many font sizes

Using 10+ different sizes across a single screen with no systematic relationship

Users cannot determine information hierarchy. Every element competes for equal attention.

Define a type scale with a maximum of 6-8 size steps. Every size must have a purpose and a consistent usage rule.

Ignoring x-height differences

Pairing fonts without checking if their x-heights are compatible

Body text appears inconsistently sized even when the same font-size is applied to both fonts

Always compare fonts at the same size and weight. Adjust sizes until optical weight feels matched.

Insufficient contrast

Using light grey text on white backgrounds, or thin font weights at small sizes

WCAG failure. Text fails accessibility standards. 25% of users struggle to read low-contrast text.

Maintain minimum 4.5:1 contrast ratio for body text (WCAG AA). Use 7:1 for AAA. Never use font-weight 100-200 for UI text.

Line height too tight

Setting line-height to 1.0 or 1.1 for body text

Ascenders and descenders collide. Text becomes a visual wall. Reading speed drops significantly.

Use 1.5-1.7 for body text. Only use tight line-height (1.1-1.2) for display text 36px and above.

Justified text in UI

Applying text-align: justify to body copy on screens

Creates uneven word spacing (rivers of white space) that disrupts reading flow and fails users with dyslexia.

Always use left-aligned text for UI body copy. Reserve centered text for short, isolated elements only.

Paragraph lines too wide

Allowing text blocks to stretch to full screen width (60+ characters per line)

Eye fatigue. Users lose their place moving from end of one line to start of the next.

Target 55-75 characters per line (CPL). Use max-width on text containers: typically 60-70ch or 640-720px.

No optical sizing

Using a single font size token for all contexts regardless of screen size or density

Text that looks right on desktop is too small on mobile and too large on wide screens

Use responsive typography with viewport-relative units or media query breakpoints in your token system.

Decorative fonts for body

Using script, display, or highly stylised fonts for reading text

Legibility collapse. Users disengage after 1-2 sentences of effort.

Reserve decorative and display fonts exclusively for headings 24px and above, with extreme brevity.

💡 Key Takeaways

Typography System

A documented set of rules governing type across a product - not a font choice, a design infrastructure.

Backbone of UI

70-90% of UI is text. Typography determines readability, trust, hierarchy, and brand expression simultaneously.

Type Anatomy

X-height is the most critical measurement for screen readability. High x-height = readable at small sizes.

Serif vs Sans-Serif

Sans-serif wins for body text on screens. Serif is excellent for display text and editorial contexts.

Modular Scale

Use a ratio (1.125 to 1.333) applied to a base size to generate a harmonious, systematic type scale.

Readability

Line height 1.5-1.7 for body. Letter spacing negative for large type, open for small. 55-75 CPL paragraph width.

Design System Tokens

Every type setting becomes a named token. Tokens enable consistency, scalability, and single-point updates.

Font Pairing

Maximum 2 families. Contrast without conflict. Shared DNA. Always test with real content at real sizes.

Responsive Typography

Type must adapt across devices. Use clamp() for fluid scaling. Never drop below 14px on any device.

Common Mistakes

Too many sizes, insufficient contrast, wrong line height, full-width text, decorative fonts for body.
