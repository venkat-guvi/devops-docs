Part 1: Introduction to Typography System

What is a Typography System?

A typography system is a deliberate, documented set of rules that governs how type is used across a product. It is not just choosing a font - it is defining every dimension of how text behaves: size, weight, spacing, family, and hierarchy.

The keyword is system. Individual type choices are design decisions. A typography system is a design infrastructure that makes consistent, scalable, and accessible type decisions possible across an entire product and team.

How Typography Signals Trust

Consistent type hierarchy signals that the product was built with care and intention

Readable body text signals that the product respects the user's time and effort

Appropriate font choice for the domain signals domain competence: a medical app using a clean, readable sans-serif signals professionalism

Poor typography signals neglect: if the text is inconsistent, users assume other aspects of the product are too

Research finding: Stanford Web Credibility Research found that typography and visual design are among the top factors users cite when evaluating website credibility

Part 3: Understanding Type Anatomy

The Baseline System

Type Anatomy Reference

Anatomical PartDefinitionWhy It Matters in UI Design
BaselineThe invisible line on which most letters sit. The foundation of vertical alignment in type.Affects text alignment and optical weight distribution in UI
Cap HeightThe height of uppercase letters measured from baseline to top of a capital letter.Determines the visual size and weight of headings in UI
X-HeightThe height of lowercase letters (specifically the letter x). Critical for readability.High x-height = more readable at small sizes. Major factor in choosing body fonts.
AscenderThe part of a lowercase letter that rises above the x-height (b, d, f, h, k, l, t).Ascenders add verticality and elegance. Affects minimum line-height requirements.
DescenderThe part of a lowercase letter that drops below the baseline (g, j, p, q, y).Descenders need space - affects line-height setting and vertical rhythm in layouts.
CounterThe enclosed or partially enclosed space within a letter (o, e, a, p, d).Large counters improve readability at small sizes and on low-resolution screens.
StemThe main vertical or diagonal stroke of a letter - the primary structural element.Stem weight determines font weight. Thin stems = light, thick stems = bold.
SerifSmall decorative strokes at the ends of letter strokes (present only in serif typefaces).Serifs aid reading at large sizes in print. Sans-serif outperforms at small screen sizes.

Family AttributeWhat It MeansDesign System Guidance

Part 5: Type Scale Deep Dive

What is a Type Scale?

A type scale is a structured set of font sizes that increase at a consistent ratio. Rather than choosing sizes arbitrarily, a type scale creates a mathematical relationship between every size level - producing visual harmony across all text elements.

When you look at a well-designed product and every heading and body text feels like it belongs together, that is a type scale working correctly. When sizes feel random and disconnected, there is no scale.

The Modular Scale

The modular scale uses a single base size and a ratio to generate all other sizes. The most common ratios produce harmonious progressions because they are based on musical intervals and mathematical constants.

Scale NameRatioProgression from 16px BaseBest For

Major Second1.12516 / 18 / 20.3 / 22.8 / 25.6 / 28.8The most common UI scale. Enough difference to read hierarchy, tight enough for screens.
Minor Third1.20016 / 19.2 / 23 / 27.6 / 33.2 / 39.8Editorial and content-heavy products. Clear hierarchy, works well for article layouts.
Major Third1.25016 / 20 / 25 / 31.3 / 39.1 / 48.8Marketing sites, landing pages, brand-led products with expressive type hierarchy.

Golden Ratio1.61816 / 25.9 / 41.9 / 67.8 / 109.7Display and poster design. Extreme contrast - almost never appropriate for UI body text.

Part 7: Typography in Design Systems

A typography design system is the formalisation of all type decisions into a set of documented, reusable tokens. Tokens replace ad-hoc decisions with a shared language between designers and engineers.

What are Typography Tokens?

A design token is a named variable that stores a design decision. Instead of a designer specifying 16px bold in every text element, they specify the token --font-size-base and --font-weight-bold. The token can be updated in one place and propagated everywhere instantly.

Semantic vs Primitive Tokens

A mature token system has two layers: primitive tokens that define the raw values, and semantic tokens that define the purpose. Semantic tokens are what designers and engineers use in practice. Primitive tokens are what semantic tokens reference.

Primitive Tokens (Raw Values)Semantic Tokens (Purposeful Names)
--font-size-16: 16px--body-font-size: var(--font-size-16)
--font-size-24: 24px--heading-3-size: var(--font-size-24)
--font-weight-700: 700--heading-font-weight: var(--font-weight-700)
--line-height-160: 1.6--body-line-height: var(--line-height-160)
These define what exists in the systemThese define how values are used
Changed only when the base design language changesChanged when purpose or context changes without changing the raw value

Consistency Checklist for Typography in Design Systems

Every text style in Figma corresponds to a named token in the code

No text element uses a local style (one-off size or weight not in the system)

Font weights are referenced by token, not by numeric value

Line-height and letter-spacing are defined in the text style, not applied as overrides

The design system documentation includes a usage guide: when to use each level, with examples

Design system changes go through a versioning process: no silent updates to token values

Part 8 : Font Pairing Principles

The Core Principles of Font Pairing

Principle 1 - Contrast, not conflict: Paired fonts must be different enough to serve distinct roles but similar enough to feel intentional. The goal is productive contrast, not visual fighting.

Principle 2 - Shared DNA: The best pairings share subtle similarities - similar x-height, similar proportions, or a shared historical period - that creates subconscious harmony despite surface differences.

Principle 3 - Maximum two families: Most UI products use one or two typeface families. Three is occasionally acceptable. Four or more is always wrong.

Principle 4 - Function defines pairing: Identify the role (heading vs body vs code vs accent) before choosing fonts. Pair for function, not preference.

Principle 5 - Test with real content: A pairing that looks good with placeholder text may fail with actual product copy. Always test with real headlines and real paragraphs at real sizes.

Proven Font Pairings for UI Design

Common Pairing Mistakes

Pairing MistakesWhy They Fail
Two sans-serif fonts with similar proportionsNo contrast = no hierarchy. The fonts blend together. Users cannot distinguish heading from body.
Two serif fonts of similar styleSame problem - too similar. Feels monotonous without variety. No clear role differentiation.
Decorative display font for both heading and bodyBeautiful for one word. Unreadable at paragraph length. The heading font was never designed for body text.
Fonts from completely different historical eras without intentional reasonThe visual tones clash. A 16th-century humanist serif paired with a 1990s techno display font reads as confusion, not sophistication.
Pairing fonts with very different x-heights at the same sizeText elements appear mismatched in size even when the font-size value is identical.
Using three or more typeface families in one productVisual complexity overwhelms the content. Users unconsciously perceive inconsistency and brand incoherence.

Part 9 : Responsive Typography

How Typography Behaves Across Devices

Device ContextTypical ViewportTypography Adjustments Needed
Large Desktop (1440px+)Wide, high-resolutionDisplay text can be 64-96px. Body text at 16-18px. Maximum line length rules become critical.
Standard Desktop (1280px)Standard work contextH1 at 48-56px. Body at 16px. Type scale performs as designed.
Small Laptop (1024px)Often used at angle/distanceH1 scales down to 40-48px. Body stays at 16px. Container widths reduce, so line length self-manages.
Tablet (768px)Touch interaction primaryH1 at 36-40px. Body at 15-16px. Touch targets (buttons, links) need larger minimum sizes - 44px minimum.
Mobile (375-430px)One-thumb use, small screenH1 at 28-36px. Body at 14-16px. Tight vertical space means spacing must compress proportionally.
Small Mobile (320px)Edge case but must workH1 at 24-28px. Body at 14px minimum. Every pixel counts. Never drop below 14px body text.

Part 10 : Common Typography Mistakes in UI

These are the most damaging and most frequent typography errors found in real UI products. Understanding them is the fastest way to elevate your type decisions immediately.

MistakePatternImpactFix
Too many font sizesUsing 10+ different sizes across a single screen with no systematic relationshipUsers cannot determine information hierarchy. Every element competes for equal attention.Define a type scale with a maximum of 6-8 size steps. Every size must have a purpose and a consistent usage rule.
Ignoring x-height differencesPairing fonts without checking if their x-heights are compatibleBody text appears inconsistently sized even when the same font-size is applied to both fontsAlways compare fonts at the same size and weight. Adjust sizes until optical weight feels matched.
Insufficient contrastUsing light grey text on white backgrounds, or thin font weights at small sizesWCAG failure. Text fails accessibility standards. 25% of users struggle to read low-contrast text.Maintain minimum 4.5:1 contrast ratio for body text (WCAG AA). Use 7:1 for AAA. Never use font-weight 100-200 for UI text.
Line height too tightSetting line-height to 1.0 or 1.1 for body textAscenders and descenders collide. Text becomes a visual wall. Reading speed drops significantly.Use 1.5-1.7 for body text. Only use tight line-height (1.1-1.2) for display text 36px and above.
Justified text in UIApplying text-align: justify to body copy on screensCreates uneven word spacing (rivers of white space) that disrupts reading flow and fails users with dyslexia.Always use left-aligned text for UI body copy. Reserve centered text for short, isolated elements only.
Paragraph lines too wideAllowing text blocks to stretch to full screen width (60+ characters per line)Eye fatigue. Users lose their place moving from end of one line to start of the next.Target 55-75 characters per line (CPL). Use max-width on text containers: typically 60-70ch or 640-720px.
No optical sizingUsing a single font size token for all contexts regardless of screen size or densityText that looks right on desktop is too small on mobile and too large on wide screensUse responsive typography with viewport-relative units or media query breakpoints in your token system.
Decorative fonts for bodyUsing script, display, or highly stylised fonts for reading textLegibility collapse. Users disengage after 1-2 sentences of effort.Reserve decorative and display fonts exclusively for headings 24px and above, with extreme brevity.
💡 Key Takeaways
Typography SystemA documented set of rules governing type across a product - not a font choice, a design infrastructure.
Backbone of UI70-90% of UI is text. Typography determines readability, trust, hierarchy, and brand expression simultaneously.
Type AnatomyX-height is the most critical measurement for screen readability. High x-height = readable at small sizes.
Serif vs Sans-SerifSans-serif wins for body text on screens. Serif is excellent for display text and editorial contexts.
Modular ScaleUse a ratio (1.125 to 1.333) applied to a base size to generate a harmonious, systematic type scale.
ReadabilityLine height 1.5-1.7 for body. Letter spacing negative for large type, open for small. 55-75 CPL paragraph width.
Design System TokensEvery type setting becomes a named token. Tokens enable consistency, scalability, and single-point updates.
Font PairingMaximum 2 families. Contrast without conflict. Shared DNA. Always test with real content at real sizes.
Responsive TypographyType must adapt across devices. Use clamp() for fluid scaling. Never drop below 14px on any device.
Common MistakesToo many sizes, insufficient contrast, wrong line height, full-width text, decorative fonts for body.
