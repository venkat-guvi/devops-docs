01 Accessibility Fundamentals

WCAG Principles — Perceivable · Operable · Understandable · Robust

WCAG (Web Content Accessibility Guidelines) defines four core principles that all digital interfaces must satisfy. In ecommerce, failing any one of these means real users cannot complete purchases.

P — PerceivableUsers must be able to see/hear contentO — OperableUsers must be able to interact (buttons, navigation)U — UnderstandableUsers must be able to interact (buttons, navigation)R — RobustWorks across devices, browsers, assistive tech

02 Types of Disabilities

Each disability type creates specific barriers in ecommerce flows. Designing for the hardest user first means your product becomes better for everyone — including users on slow connections, in bright sunlight, or holding a baby one-handed.

👁 Visual DisabilityBlindness · Low Vision · Color BlindnessProblem: No alt text, color-only signalsFix: Alt text + labels + don’t rely only on color🤚 Motor DisabilityTremors · Paralysis · Limited DexterityProblem: Small buttons, swipe/hover actionsFix: ≥44px targets + simple tap interactions
👂 Auditory DisabilityDeafness · Hard of HearingProblem: Videos without captionsFix: Captions + visual indicators🧠 Cognitive DisabilityADHD · Dyslexia · Memory IssuesProblem : Amazon's checkout has 6+ steps with inconsistent UI across steps. No progress indicator. Users with ADHD lose track, abandon carts. Dyslexic users struggle with dense text and small line heights in specs.Fix: Progress steps + simple, readable content

03 Test Planning & Execution

Before any user sits in front of your product, the UX team builds a test plan. This plan defines exactly what you're testing, who you're testing with, and how you'll measure success. Without a plan, you're just watching someone shop — not learning anything actionable.

What a test plan covers:

Participants: target users (age, device, behavior, accessibility)

Tasks: real scenarios (e.g., “Find a phone under ₹30K”)

Metrics: success rate, time, errors, SUS score

Structure: moderated/unmoderated, session flow

04 Usability Testing

Watching real users navigate your ecommerce flow — and learning from where they break

Usability testing is not asking users "do you like this?" It's watching them try to complete real tasks and observing where they struggle, hesitate, or fail. On an ecommerce product, the flow is always: Product → Cart → Checkout.

What usability testing reveals:

Exactly where users hesitate, backtrack, or abandon

Whether your button labels match what users expect to do

Which UI elements are being ignored vs. interacted with

Confusion points that no amount of analytics data explains

05 Types of Testing Methods

Moderated vs Unmoderated — when to use each, and what you learn

Neither method alone is enough. The best UX teams combine both — moderated sessions to discover problems and understand the "why," then unmoderated tests to validate fixes at scale before shipping.

Factor🎙 Moderated Testing📊 Unmoderated Testing
Sample size5–8 (enough for patterns)20–50+ (statistical confidence)
Turnaround1–2 weeks (scheduling)24–48 hours
Output typeQuotes, observations, the "why"Metrics, heatmaps, click paths
Best forComplex flows, new features, accessibilityValidating hypotheses, A/B decisions
Example useTesting new Flipkart return flowValidating 'Add to Cart' button copy change

06 Analyzing Feedback & Iteration Cycle

Testing → Insight → Design Fix → Better UX

Raw session data means nothing until it's organized into themes. The affinity mapping process turns scattered observations into prioritized design problems — and those problems into specific UI changes you can measure in the next round.

🔬 Test → 📋 Synthesize → 🎯 Prioritize → ✏️ Redesign → ✅ Retest

Each step feeds the next. After retesting, the cycle starts again. UX is never "done" — every shipped improvement creates new behavior to observe.
