Containers vs. Virtual Machines

What is a Container?

A Container is a standardized, lightweight unit of software that packages application code along with all its runtime dependencies, libraries, and configuration files so it runs quickly and reliably across any computing environment.

🖥️ Virtual Machines (VMs)

  • Requires a Hypervisor (Type 1 or Type 2)
  • Includes a complete Guest Operating System per VM
  • Heavy RAM & disk footprint (gigabytes)
  • Slow boot time (minutes)

📦 Docker Containers

  • Shares the Host OS Kernel
  • No Guest OS required per application
  • Lightweight footprint (megabytes)
  • Instant startup time (milliseconds to seconds)
💡 Why Docker? Portability, lightweight isolation, rapid scalability, high performance, and environment consistency from developer laptops to cloud production servers.

Docker Client-Server Architecture

Inside Docker Engine

Docker uses a Client-Server architecture where the CLI client sends REST API commands over UNIX sockets or network sockets to the background daemon.

💻

Docker Client

The primary user CLI interface (docker command) that sends user instructions to the daemon.

⚙️

Docker Host & Daemon

The background service process (dockerd) responsible for building, running, and managing containers and images.

☁️

Docker Registry

Centralized repository server storing container images (e.g. Docker Hub public registry or private registries).

Architecture Flow:
Docker Client (CLI)  ━━▶  REST API / Socket  ━━▶  Docker Daemon (dockerd)  ━━▶  Images / Containers

Dockerfile Development & Instructions

Building Custom Container Images

A Dockerfile is a text manifest containing step-by-step instructions for assembling a custom container image layer by layer.

InstructionDescription & Usage
FROMDefines the base parent image (e.g. FROM ubuntu:20.04 or FROM node:18-alpine).
WORKDIRSets the default working directory inside the container for subsequent instructions.
COPYCopies files from the host machine into the image filesystem (COPY package.json .).
ADDSimilar to COPY, but automatically unpacks local tar archives and fetches URLs.
RUNExecutes build-time commands (e.g. installing dependencies) and creates a new image layer.
ENVSets environment variables accessible during container runtime (ENV PORT=8080).
EXPOSEInforms Docker that the container listens on specified network ports at runtime.
CMDSets default execution command for container runtime. Overridden by CLI arguments.
ENTRYPOINTSets fixed execution binary for container runtime. Appends CLI arguments.
VOLUMECreates a mount point directory for external volume attachment.
USERSets non-root UID/GID for container runtime execution (security best practice).
# Production-Ready Nginx Dockerfile Example
FROM nginx:alpine
LABEL maintainer="devops@company.com" version="1.0"
COPY nginx.conf /etc/nginx/nginx.conf
COPY ./html /usr/share/nginx/html
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]

Docker Networking & Drivers

Container Communication

Docker virtual networks allow containers on the same host or across different hosts to communicate seamlessly over isolated network bridges.

Network DriverBehavior & IsolationUse Case
Bridge (Default)Private software network isolated on the host. Containers get private IPs.Standard standalone containers on single host
HostRemoves network isolation. Container uses host network interfaces directly.High performance, high throughput workloads
NoneDisables all networking. Container has no IP or external access.Isolated batch processing or secure compute
OverlayConnects multiple Docker daemons across different hosts.Docker Swarm / Multi-host cluster networking
$ docker network create my-net   # Create custom bridge network
$ docker run -d --net my-net --name db redis
$ docker run -d --net my-net --name web my-web-app   # Web connects to db via hostname

Docker Storage & Volumes

Union File System & Data Persistence

Docker images consist of read-only layers. When a container runs, Docker adds a temporary Read-Write container layer on top. Using Docker Volumes ensures data persists even after containers are deleted.

📂

Named Docker Volumes

Managed directly by Docker on the host filesystem (/var/lib/docker/volumes/). Recommended for database storage.

🔗

Bind Mounts

Mounts any arbitrary host directory or file directly into the container (-v /opt/data:/app/data). Great for development live-reloading.

$ docker volume create db-data   # Create named volume
$ docker run -d -v db-data:/var/lib/postgresql/data postgres

Docker Registry vs. Repository

🌐 Docker Registry

A central service/server that stores and distributes container images (e.g. Docker Hub, Amazon ECR, GitHub Container Registry).

📁 Image Repository

A collection of related container images within a registry under a project name (e.g. nginx:latest, nginx:alpine).

# Image Tagging & Archiving Commands
$ docker tag my-app:latest myrepo/my-app:v1.0   # Tag image
$ docker save my-app:latest > my-app.tar   # Export image to tar file
$ docker load < my-app.tar   # Load image from tar archive

Multi-Container Orchestration with Docker Compose

Defining Multi-Container Applications as Code

Docker Compose allows you to define and run multi-container applications (frontend, backend API, database) using a single docker-compose.yml declarative YAML manifest.

# Sample docker-compose.yml
version: '3.8'
services:
  web:
    build: .
    ports:
      - "8080:80"
    depends_on:
      - db
  db:
    image: postgres:alpine
    environment:
      POSTGRES_PASSWORD: secret
Compose CommandAction
docker compose up -dBuilds, creates, and starts all services in detached background mode
docker compose downStops and removes all containers, networks, and volumes created by Compose
docker compose psLists all running services managed by current Compose stack
docker compose logs -fTails logs across all multi-container services simultaneously

Container Security Best Practices & Cheat Sheet

📦

Use Minimal Base Images

Prefer minimal Linux base images (e.g. Alpine) to reduce attack surface and vulnerability count.

👤

Avoid Running as Root

Always specify a non-root USER in your Dockerfile to prevent privilege escalation.

🔍

Vulnerability Scanning

Scan container images for CVE vulnerabilities using scanners like Trivy or Docker Scout before deployment.
